# Notes: typed reflection (metaprogramming) for the cell language

Parked 2026-11-14, from a discussion with Tom. Nothing here is built. These notes record what was decided,
what was measured, and the order of work proposed.

## Where it stands

- RULES.md:17-18 puts "anything reflective" in `shell.ts`, so it is unchecked. The one port that met it:
  lopepage-urls `vars` is `variables(runtime)`, a live set of runtime `Variable` objects, kept as two shell
  cells (`ports/lopepage-urls/GAPS.md:49-65`). A third shell cell in that port, `_3 = (tests) => tests()`
  (`shell.ts:7-8`), walks the runtime through an import; it is outside step 3 below.
- `plan/substrates-winter-2026.md` §"03 output" prototyped a declared capability: `editor` takes a
  `thisModule` input whose only method is `redefine`. In that run `editor.bumpX()` reran exactly the cells
  downstream of `x`, and a cell that went looking for the runtime as a global got `undefined`. A reflective
  *read*, the replacement for runtime-sdk's `observe`, was not prototyped.

## Decided (Tom, 2026-11-14)

- **Stay TypeScript-compatible.** A type system with more set theory was considered and dropped: TS is more
  understandable and good enough. "Name is in the set" is written `K extends keyof C`.
- **The capability enters at the module.** We want our own typed reified representation of `Runtime`,
  `Module` and `Variable`; a cell gets `Module<ThisModule>`.
- **A change type-checks its cascade.** A change that can alter a cell's type rechecks every cell
  downstream of it. In the sketch below `redefine` is held to the cell's current type `C[K]`, so only the
  new cell needs checking; `define`, or any redefinition allowed to change the type, rechecks downstream.
- **Typed templates are the target for generated code,** reached after a shortcut (below).
- **A Variable's argument signature is a tuple** of its definition's parameter types.

## Shape (sketch, not checked by either checker)

```ts
interface Variable<T, Args extends readonly unknown[]> {
  readonly name: string;
  readonly definition: (...args: Args) => T;
  readonly inputs: { readonly [K in keyof Args]: Variable<Args[K], readonly unknown[]> };
  readonly value: RefCell<T>;                 // reading it is a graph edge
}
interface Module<C extends Record<string, unknown>> {   // C: cell name -> value type
  variable<K extends keyof C & string>(name: K): Variable<C[K], readonly unknown[]>;
  redefine<K extends keyof C & string>(name: K, cell: Cell<C, C[K]>): Action;  // keeps the type: recheck the cell
  define<K extends string, T>(name: K, cell: Cell<C, T>): Action;              // recheck downstream
}
```

`ThisModule` is generated by the harness from the value types lite already infers for every cell
(`bun lite/check.ts <port> --json`, field `value`).

**Shortcut for templates:** `Cell<C, T>` is a source string plus its claimed type. lite checks it against
`Module<C>` when `define` runs and refuses it before anything is installed. The later typed `cell` template
tag (holes are typed `Variable`s) replaces only how a `Cell` value is built; `Module`'s interface stays.
Rechecking a whole module costs 6–13 ms per port in process (`bun lite/oracle.ts`, 2026-11-14), so the first
version may recheck the whole module rather than only what is downstream.

## What lite supports today (probe, 2026-11-14)

Generic interfaces, generic aliases with several parameters and rank-1 generic functions work, and lite and
`bun check.ts` agree on the error. The probe is `fixtures/lite-types/reject-generics/`:

```
$ bun lite/check.ts fixtures/lite-types/reject-generics
cells.ts:7 bad_read [type] number | undefined is not assignable to string | undefined
cells.ts:8 uns_constrained [unsupported] type parameter constraint/default
$ bun check.ts fixtures/lite-types/reject-generics
.../cells.ts:7:59 [ts2322] Type 'number | undefined' is not assignable to type 'string | undefined'.
```

Missing, needed by the shape above:

| feature | needed for | note |
|---|---|---|
| bounds, at least against a literal union | `K extends keyof C` | lite reports any constraint as unsupported |
| `keyof` and indexed access `C[K]` | `Module<C>.variable(name)` | `keyof` is unsupported (`registry.ts`, "type operator keyof") |
| rest parameter typed by a tuple | `(...args: Args) => T` | `registry.ts:86` accepts only an array rest type |
| inferring a tuple `Args` from a parameter list | reifying a cell as `Variable<T, Args>` | unification is one parameter at a time |
| mapped tuple types | typed `inputs` | can be deferred: `define`/`redefine` can check that each input's type is assignable to the matching parameter instead |

## Proposed order

1. Literal-union bounds, `keyof`, indexed access on record types.
2. Tuple rest parameters and inferring `Args`.
3. Prelude types `Runtime`, `Module<C>`, `Variable<T, Args>`; `ThisModule` generated; port lopepage-urls
   `vars` out of the shell as the first case.
4. Wiring check and cascade recheck on `define`/`redefine`; then typed templates; mapped tuples last.

Each step gets a `fixtures/lite-*` case run through both checkers.

## Open

- Should a cell's name be part of its type (`Variable<"x", T, Args>`)? Then `inputs` could say which
  cells, not only which types. It costs string literal types throughout, which make inferred types longer.
- `define` adds a name, but `Module<C>` keeps the same `C`, so `variable("newCell")` would then fail
  `K extends keyof C`. Either `define` returns `Module<C & Record<K, T>>`, or the harness regenerates
  `ThisModule` after every define. Not decided.
- Not counted: how many corpus modules do reflective reads, reflective writes, or source generation.
