## What the tutorial did not tell me

Most consequential first.

0. **The listings for section 4's async half and section 10 are not in the material.** The tutorial draws them from `./tutorial-async.tsx` and `./tutorial-ordinary.tsx`, which are not in `examples/`. So the async cell → events → listener → action pattern (29, 33) and reading ordinary cells came from prose only.
1. **How to get the clock into an action that the page calls with no arguments** (29). Actions may not use `now`; `onClick` is `Action<[]>`. The tutorial says clock values arrive "from an events cell or a view" but never shows a view supplying one. I invented a clock-into-state listener.
2. **How to write a per-row button handler** (34). The tutorial forbids the natural form and offers only an `input` checkbox workaround ("A `button` carries no value, so this form needs an `input`."). It does not say whether `action(...)` may be made inside a `map` callback over non-state data, or stored in an array.
3. **Whether a cell's value may be a generic function, and whether generic type aliases (`type Stack<T>`), `extends` bounds and explicit type arguments are supported** (10, 16, 39, 40). Generic functions are implied by the `[handle-pass]` sentence ("a type parameter of a function of the module"); nothing shows one as a cell's value, a generic alias, or an explicit type argument, and "Not built" says the checker lacks bounds.
4. **How to build an object with private mutable state** (16 LRU). The rules imply it cannot be done (no capture of a `Mut`, values frozen); the tutorial never says "use an immutable value and return a new one" for this case.
5. **The members of `FetchResponse`** (32): `ok`, `status`, `text()` are not listed; only `json()` is shown.
6. **What `messageOf` does** (32). It is listed in the prelude and never described.
7. **Which intrinsic members are declared** (`padStart`, `padEnd`, `localeCompare`, `includes`, `flatMap`, `charAt`, `RegExp.test`, `Number.isInteger`). The tutorial says undeclared members are *unsupported* but gives no list.
8. **Whether "a nested function may not hold one [response]" forbids a helper that fetches and reads its own response** (31), and how `[mut-await]` treats a `Mut` bound from one `await` and used in the next.
9. **Whether a local helper that captures a `Mut` and is called immediately (e.g. a `map` or a recursive walk) "outlives the call that made it"** (03, 07, 13). Half answered: "How good is the checker" mentions "three helpers capturing a Mut (allowed deliberately)", but the language reference does not state the rule. I avoided the pattern everywhere.
10. **Whether values obtained with `read(...)` inside an action count as "a local computed from" state for `[action-capture]`** when used in an `update` callback (18, 29, 36).
11. **What a state cell may hold**: `Set`, `Map`, index-signature records (23, 25). Only `undefined` and nested state are named as forbidden. (Index-signature types themselves exist: the `[no-delete]` row mentions "an index-signature entry".)
12. **What "record annotation" means** for writability (39): whether `{ [k: string]: T }` or `Record<K, V>` counts.
13. **Whether string index reads (`s[i]`) and typed-array and tuple index reads are `T | undefined`** like array reads (03, 07, 14, 15, 28). Example 03's `bins[…] += 1` shows a typed-array element update is accepted, which suggests typed-array reads are not `T | undefined` there, but it is not stated.
14. **Dates**: `Date` is removed and no replacement or recommended approach is given (09).
15. **Names**: the full list of "the checker's own types" (`[builtin-type-name]`), so I avoided `Result`, `Event` and `Card` and could not tell whether `History` (20) collides; whether `listen` is reserved (28); whether types and cells share a namespace (37).
16. **Whether `?.` optional member access is supported** (05, 21); only `??` appears.
17. **Whether an exhaustive `switch` counts as returning on every path** (24), and whether an action body may `return` early (36).
18. **Whether a generator whose input is an async cell receives the resolved value** (33). (A generator that returns is shown: example 09's `ticks` does `if (!playing || over) return;`; I missed that while writing 28.)
19. **JSX prop value types**: whether `input value` takes a string or number, whether `type="number"` is allowed, and whether a `button` without `onClick` is accepted (19). The appendix with the declarations is rendered at run time and is not in the tutorial's source.
20. **Whether a union child (an element or an array of elements) is accepted** (35). (Optional fields exist: the `[no-delete]` row says "allowed on a `Mut` when `b` is optional".)
