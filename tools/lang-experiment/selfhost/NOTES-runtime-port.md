## Two limits on landing, independent of the body

1. **A cell that uses a built-in takes `ss`.** `compileCell` emits `{ const {mut, freeze} = ss; … }` for any prelude
   name the body uses. `ss` is the runtime module's object of its own cells, so such a cell in the runtime module
   is a cycle for every cell upstream of a member of `ss` (nearly all of them). Measured
   (`check.ts lite/types.ss.ts --compile`): `union: ok … inputs=[ss,show,ERR,UNKNOWN,NEVER]`, `show: … inputs=[]`.
2. **An SS cell cannot take a JavaScript cell's function, Map or symbol.** With the neighbours named outside
   (`check.ts selfhost/rt/probe-boundary.ss.ts --outside rt,stores,STATECELL,nameOf --compile`):
   ```
   idle: rejected  [boundary-type] L3 rt: Rt cannot cross from another language: it is or holds call: Map<string, unknown>, which the boundary does not check
   viaSym: rejected  [boundary-type] L11 STATECELL: symbol cannot cross from another language: it is or holds symbol, which the boundary does not check
   viaFn: rejected  [boundary-type] L13 nameOf: (a: object) => string cannot cross from another language: it is or holds a function
   depth: ok … inputs=[ss,rt]        (a data-only record crosses, but through ss.cross, so limit 1 again)
   ```
   So a landable set is a closed subgraph: cells that take only other SS cells and use no built-in. JavaScript
   cells may take SS cells; that direction is unchecked (a JS caller passes what it passes).

## If the (c) gaps were closed

None of the runtime's containers would become a `state(...)` cell. `state(...)` cells, actions and commits are
implemented by `rt`, `stores`, `over`, `views`, `runs`, `write`, `commit`, `ref`, `action`; a state cell's store is
what `stores` holds. The other containers are written during cell evaluation, by the host, or are caches:
`crossings` and `last` are written in `cross`, which runs while a compiled cell's arguments are evaluated. As a state
cell (`selfhost/rt/probe-state.ss.ts`):
```
crossings: ok : { copies: number; reused: number }                  (= state({ copies: 0, reused: 0 }))
cross: rejected      [state-write] L5 State.set/update outside action(...)
crossVia: rejected   [action-call] L11 an Action called outside action(...)   (through an action instead)
```
`actionNamer`, `placeOf` (`setListenerOrder`) and `scheduler` are set by the host or by tests; `joined`, `runs`,
`views` are caches. None is written only by actions.

Upper bound of what closing ranking 1 and 3 and the intrinsics would move to (a): reflection 5, symbols 9,
intrinsics 3, Mismatch/checkShape 2 = 19 declarations, 126 lines (18% and 19%). Not all of them: `copy` also hit
`[unsupported] try/finally in a function holding a Mut/Borrowed` and `[mut-capture] Mut seen captured by a function
that escapes`, and `copy`/`cross`/`checkShape` call `mut`, so in the runtime module they also need ranking 2. `cross`'s
memo (`last`, `crossings`) stays JavaScript either way.

Stays JavaScript, as written: the store and commit machinery (`rt`, `stores`, `write`, `commit`, `ref`, `action`,
`run`, `finish`, `pump`, `entry`), event delivery and generator pulling (`hs`, `events`, `kick`/`pull`, `deliver`,
`listen`, `sweep`), the DOM renderer (`create`, `patch`, `mount`), the worker pool (`makePool`, `pagePool`, `EXEC`),
the handles (EventTarget with defined properties), every cache: the (d) row, 56 declarations, 454 lines, 69%. That
is an upper bound for "regardless": only `orderOf` was split, and it had a pure part (15 lines → 10 in SoundScript).
Not attempted, by reading: `patch`'s keyed matching (which old child each new keyed child reuses, and which are
removed, is a function of two key lists), `action`'s choice between throw / inline call / run now / queue (a
function of `evalDepth`, `actionDepth`, whether a call is in flight, `entry`, `waiting.length`), `ref`'s keep test
(`last.id === id` and `same(args, last.args)`). Each split leaves the writes in JavaScript.

## Language changes that would unlock the most (ranked)

1. Reflection over `unknown` data: an `object` (after narrowing) readable by a string key as `unknown`,
   `Object.entries`/`keys` on it, `Object.getPrototypeOf`/`hasOwn`/`freeze`/`isFrozen`, and `instanceof` against
   intrinsic constructors (Map, Set, Error, Array, typed arrays). Unlocks `equals`, `deepEqual`, `describe`, `plain`,
   `copy` (with the Result rewrite), `snapshot`, `h` (~7 declarations, ~110 lines). Cost: ~6 declaration lines in
   intrinsics.ts; an index rule on `object` in infer.ts (~5 lines); `instanceof` narrowing (~25 lines, infer.ts
   `cond`, plus own.ts if a Mut can be its operand). Spec: S2.6, S9.2, a new statement for `instanceof`. Simplicity:
   `instanceof` brings nominal tests into a structural checker; an index read on `object` is unchecked data access
   (a getter on a value from `catch` would run).
2. Built-ins without `ss` in the runtime module: `mut`, `freeze`, `borrow` are identities at run time, so the compiler
   could erase them in that module instead of reading them from `ss` (ss-toolchain `used`, ~10 lines). Unlocks landing
   any runtime cell that uses a local Mut (`copy`, `cross`, `checkShape` after 1). Spec: none (compiled form only).
   Simplicity: two compiled shapes for one cell, depending on the module.
3. Symbols: a `Symbol`/`Symbol.for` signature, symbol-typed computed keys in literals and types, `in` with a symbol.
   Unlocks 9 one-line cells, all brands of (d) containers. Cost: intrinsics 2 lines; computed keys in infer.ts
   (~15); a second key space for record props in registry.ts (~30). Spec: S2.6 and the record type statement.
   Simplicity: record types gain non-string keys.
4. Constructs: `switch` (own.ts dataflow, est. ~40 lines), try/finally holding a Mut (own.ts), type predicates
   (`x is T`: removes the casts in types.ts and runtime-ss.ts), `Promise.then(f, g)`/`.catch`. Each unlocks a rewrite
   rather than a cell: every cell that met one here was rewritten and landed.

### Reading values of unknown shape: three options

All three options keep these rejected: `as` casts, writes to a value of unknown shape, the two holes above, and `===` between two possibly non-primitive operands (S3.12).

**A. Narrow to a read-only record and array.**
- Rules:
  - `typeof v === "object" && v !== null` narrows `v: unknown` to `{ readonly [k: string]: unknown }`.
  - `Array.isArray(v)` narrows it to `readonly unknown[]`.
  - On that record, `v[k]` with `k: string` is `unknown`, `k in v` is allowed, and `Object.keys(v)` is `readonly string[]`.
- What it cannot do: it has no way to tell a Map, a Set or a Date from a record. `Object.keys(new Map([[1, 2]]))` is `[]`, so the `equals` below says two different Maps are equal. Because of this, A cannot port `equals` alone.
```ts
const equals = () => function equals(a: unknown, b: unknown): boolean {
  if (Object.is(a, b)) return true;
  if (Array.isArray(a)) return Array.isArray(b) && a.length === b.length && a.every((x, i) => equals(x, b[i]));
  if (typeof a !== "object" || a === null || typeof b !== "object" || b === null || Array.isArray(b)) return false;
  if (!Object.is(Object.getPrototypeOf(a), Object.getPrototypeOf(b))) return false;
  const ka = Object.keys(a), kb = Object.keys(b);
  return ka.length === kb.length && ka.every((k) => k in b && equals(a[k], b[k]));
};
```
- Estimated cost: ~35 checker lines (an index rule on the record, narrowing on `typeof`/`isArray`, the `in` operand rule) and 2 intrinsics declarations (`Object.keys` and `Object.getPrototypeOf` on unknown).
- Spec statements touched: S9.2 (it becomes PROSE PENDING) and 2 new statements.
- Cost in simplicity: an index read on unknown data runs any getter it reaches.

**B. Prelude inspection functions.**
- Signatures:
  - `kindOf(v: unknown): "null" | "undefined" | "boolean" | "number" | "bigint" | "string" | "symbol" | "function" | "array" | "typed" | "map" | "set" | "record" | "other"`. It returns `"record"` only when the prototype is `Object.prototype` or `null`, and `"other"` for handles, class instances and Dates.
  - `keysOf(v: unknown): readonly unknown[]`. It gives the own enumerable string keys of a record, the indices of an array or typed array, the keys of a map, the values of a set, and `[]` for anything else.
  - `at(v: unknown, k: unknown): unknown`. It reads an own data property through its descriptor, or `Map.get`. It never calls a getter, and it gives `undefined` for an accessor or a missing key.
- These are ordinary prelude functions. Narrowing is the existing literal comparison `kindOf(a) === "map"`, and the checker gains no new typing rule.
```ts
const equals = () => function equals(a: unknown, b: unknown): boolean {
  if (Object.is(a, b)) return true;
  const k = kindOf(a);
  if (k !== kindOf(b) || !(k === "array" || k === "typed" || k === "map" || k === "set" || k === "record")) return false;
  if (!Object.is(Object.getPrototypeOf(a), Object.getPrototypeOf(b))) return false;
  const ka = keysOf(a), kb = keysOf(b);
  if (ka.length !== kb.length) return false;
  if (k === "set") return ka.every((x) => kb.includes(x));
  return ka.every((x) => kb.includes(x) && equals(at(a, x), at(b, x)));
};
```
- This matches the original: values are compared deeply, while map keys and set members are compared by identity.
- Estimated cost: ~6 checker lines (3 prelude signatures and `Object.getPrototypeOf` on unknown) plus ~30 lines of runtime in `prelude.runtime.ts`.
- Spec statements touched: S2.6's prelude list (PROSE PENDING) and 3 new statements, one per function.
- Cost in simplicity: three names that TypeScript does not have. Ported code moves further from its original: `a instanceof Map` becomes `kindOf(a) === "map"`.

**C. `instanceof` against intrinsic constructors, on top of A.**
- Rules:
  - `v instanceof C`, with `C` one of `Array Map Set Error RegExp ArrayBuffer` or a typed array, narrows `v` to the read-only form of `C`: `ReadonlyMap<unknown, unknown>`, `ReadonlySet<unknown>`, `readonly unknown[]`, and so on.
  - The false branch keeps `v` unchanged.
  - Any other right operand is rejected (new rule, say `instanceof-non-intrinsic`).
```ts
const equals = () => function equals(a: unknown, b: unknown): boolean {
  if (Object.is(a, b)) return true;
  if (typeof a !== "object" || typeof b !== "object" || a === null || b === null) return false;
  if (!Object.is(Object.getPrototypeOf(a), Object.getPrototypeOf(b))) return false;
  if (a instanceof Map) return b instanceof Map && a.size === b.size && [...a].every(([k, v]) => b.has(k) && equals(v, b.get(k)));
  if (a instanceof Set) return b instanceof Set && a.size === b.size && [...a].every((v) => b.has(v));
  if (Array.isArray(a)) return Array.isArray(b) && a.length === b.length && a.every((x, i) => equals(x, b[i]));
  const ka = Object.keys(a), kb = Object.keys(b);
  return ka.length === kb.length && ka.every((k) => k in b && equals(a[k], b[k]));
};
```
- This is the closest to `prelude.runtime.ts` `equals`; only the casts are gone. Typed arrays fall through to `Object.keys`, which gives their indices.
- Estimated cost: A's ~35 lines plus ~25 for `instanceof` narrowing in `cond`, plus ~3 in own.ts.
- Spec statements touched: S9.2 and 3 new statements.
- Cost in simplicity: nominal tests enter a structural checker. A Map from another realm fails `instanceof` and is then compared as an empty record. That is A's failure, narrowed to foreign realms.

**Recommendation: B.**
- It adds the fewest checker lines and no typing rule; the narrowing it relies on (literal comparison) is already specified.
- `at` runs no getter.
- It is the only option where the cross-realm and Map-as-record cases cannot give a wrong answer.
- Its cost is vocabulary that TypeScript does not have.
- If staying close to the original TypeScript matters more, take C, and take it whole, since A alone cannot write `equals`.
