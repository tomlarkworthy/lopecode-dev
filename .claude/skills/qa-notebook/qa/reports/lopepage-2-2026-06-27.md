## Issues found

### 1. Deep-link `#cell` does nothing when the module is already open — severity: medium — criterion: #3
- **What:** `#open=@mod#cell` (and import links carrying a `#cell`, e.g. `#open=@mootari/access-runtime#runtime`) scrolls the pane to the named cell **only when the module is being opened fresh**. If the module's pane is already open and rendered, the scroll never happens — scrollTop stays where it was.
- **Where:** `lp2_view` rerender (lines ~534-552) vs `lp2_getPane`→`applyDeepLink`→`lp2_scrollToCell`.
- **Evidence:** Fresh open of runtime-sdk with `#onCodeChange` → scrolled to offsetTop 533, top cell `onCodeChange` (12/12 samples = 533). Already-open lopepage-2 with `#lp2_doc_hash` / `#lp2_doc_mount` → scrollTop stayed 0 across 8 samples; the target cell exists (offsetTop 3345/3345).
- **Hypothesis:** The rerender captures `saved` scroll anchors for every pane in the registry **before** `replaceChildren`, then `getPane`→`scrollToCell` synchronously sets `scrollTop=targetTop` during render, and the **post-render restore loop overwrites it back** to the pre-render value. For an already-settled pane `scrollToCell`'s first attempt succeeds immediately (within 2px) so it schedules no retry to correct the clobber. Fresh panes aren't in the pre-render `saved` map, so nothing clobbers them — hence the asymmetry. (Secondary: `applyDeepLink`'s `entry.deepLink !== deepLinkCell` guard also blocks re-firing the *same* deep-link twice.)

### 2. Splitter resizes never persist to the URL — severity: medium — criterion: #3 / #4
- **What:** Dragging a splitter resizes the panes visually and updates `node.sizes`, but the new sizes are never written to the `view=` hash, so they're lost on reload and not shareable via link.
- **Where:** `lp2_splitter` onMove writes fractional `node.sizes`; `lp2_serializeDSL` / `lp2_parseDSL` round-trip guard in `lp2_syncToUrl`.
- **Evidence:** Drag splitter 640→420px → `sizes` became `[32.8125, 67.1875]`, hash stayed `R100(S50(…),S50(…))`. Direct check: `serialize(model)` = `R100(S32.8125(…),S67.1875(…))`; `serialize(parse(that))` = `R100(S32(),.8125(@tomlarkworthy/runtime-sdk)` — `roundTrips: false`. The integer-only `num()` parser stops at `.`, mangling the float, so the round-trip guard correctly refuses to write it.
- **Hypothesis:** Splitter should round `node.sizes` to integers (e.g. in onMove or onUp), or the serializer should round. Integer sizes do round-trip cleanly.

### 3. `cc=` / non-`view=` hash params dropped on intent navigation — severity: low — criterion: #3
- **What:** Clicking an import link or firing `open=`/`close=` replaces the whole hash with a bare `#open=…`, dropping `cc=` (the pairing token) and any other hash params. `lp2_syncToUrl` then re-writes only `view=`.
- **Where:** import-link anchors render `href="#open=@mod"` (whole-hash navigation); `lp2_setHash` writes `view=` only.
- **Evidence:** After clicking the access-runtime import link, hash went `…&cc=LOPE-…` → `#view=R100(…)` with no `cc=`.
- **Hypothesis:** Inherent to bare-`#` anchor hrefs. Channel stays connected in-session (only the URL param is lost), so impact is limited to reload/copy-link. Could preserve unknown params when rewriting the hash.
