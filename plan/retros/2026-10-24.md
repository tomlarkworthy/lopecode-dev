## 2. Diagnosis

### 2.1 The record over-counts what resumed runs cost, by about 2× on 10-23

**What was seen.** `measure.py` read 305.91 USD for the 24 h, 258.01 of it worker runs, against 54.52 in the 10-22 report.
One issue's worker runs, in order:

```
db-latency-since-10z  fresh   2.03  ctx 116k  46 requests
                      resumed 3.44  ctx 153k  28 requests
                      resumed 4.53
                      resumed 6.12
                      resumed 6.30  ctx 210k   3 requests, 1,143 output tokens
                      resumed 6.95
```

Each resumed value is at least the one before. A run of 3 requests cannot cost 6.30 USD.

**The check.** Over the whole record, 80 of 80 resumed runs that carry a `usd` recorded at least the `usd` of the run
before them in their session (26 resumed runs of 10-12 carry none), and so did 95 of 95 `light` runs of the old loop's
`run.ts` that continue a session. Priced on the run's own token counts (input + 2 × cache write + 0.1 × cache read + 5 ×
output), fresh runs come to a median 3.31 USD per million; resumed runs 12.07 by their recorded `usd`, and 2.92 by the
difference from the run before. So a resumed run's `usd` is its session's total so far.

**Where.** `cloud-brain-dev/agent.sh` prints `"usd": o.get("total_cost_usd")` from claude's result line; for
`claude -p --resume` that total includes the session's earlier turns. `drain2.ts` wrote it to `issue.cost`, to
`loop.done` (the loop's daily budget, `budgetUsd` 200) and to its own sum. The token counts in the same event are the
run's own, which is how the check above could be made.

**Size.** Resumed worker runs since 10-22: recorded 245.63 USD, about 60.97 (median 0.59 a resume). By day, recorded →
about:

```
10-17 151.71 -> 137.07    10-20  68.16 ->  67.04    10-23 306.12 -> 151.31
10-18 213.07 -> 191.98    10-21  40.74 ->  39.71
10-19  92.28 ->  84.26    10-22 100.65 ->  70.80
```

Before 10-22 the excess is the old loop's `light` runs (7 d implementer 229.16 → 184.01); from 10-22 the redesign's
resumed workers.

**Why the system allowed it.** The cost of a run is taken from what the agent's process reports, and no check compares
it with the token counts beside it. Worker runs since 10-22 by the record: a resume a median 2.83 USD, a fresh run 0.84. By the
resumes' own token counts: 0.59 against 0.84.

**Would it have been caught without this run?** No reader of the record compares `usd` with `usage`. The owner's role
spend, `issue.get` cost, `issue.runs` totals and `stats.ts` all summed it.
