## 2. Diagnosis: a service patch breaks a test of this repository, and nothing runs that test before the deploy

Chosen because `main` of `cloud-brain-dev` has been red on a new test three times in four days for one cause (11-07 and 11-09 by the comment `996aaf1` put in `issues-object-tells-topic.test.ts`, and today) (line 5), each found only by this retro (line 6), and a suite that is always red hides the next red.

**What happened.**
- 11-07 and again by 11-09: `tests/issues-object-tells-topic.test.ts` built `issuesApp` with its inputs by position, and a deployed patch changed them (11-09 report, section 3 item 2).
- 11-09 18:57 UTC: `approve-link-needs-owner` deployed `brain-x-issues@b7a15bf4f430` (#42105, `deploy.verified`, `deploy.confirmed`), whose `issuesDecide` takes a second input, `issuesWaits` (`$def("_brainissues_issuesDecide", "issuesDecide", ["issuesAsker","issuesWaits"], …)`). Its review passed at 19:32 (#42249). `tests/decide-cell.test.ts` built the cell as `_brainissues_issuesDecide(_brainissues_issuesAsker())`; 4 of its 5 tests failed this morning:
  ```
  TypeError: issuesWaits is not a function. (In 'issuesWaits(issue)', 'issuesWaits' is undefined)
  ```
  That file is the check, required by spec R12 of `approve-link`, that the page's copies of `specAttachment` and `approvedRoute` answer as `accept.ts` does. Since 18:57 on 11-09 it checked nothing.

**Why the system allowed it.**
- Three files of `tests/` evaluate cells of a service module read from `deploy/`: `decide-cell.test.ts` and `issues-object-tells-topic.test.ts` (`brain-issues.js`), `loop-route.test.ts` (`brain-loop.js`).
- A service patch is checked by `bun test.ts brain-x-NAME` (`roles/worker.md` step 5, `roles/reviewer.md` step 4) and by the deployer's dry run, both of which run the module's `test_*` cells only. `deploy.ts` runs no test here. `push.ts` runs only "the tests the patch names", and a service patch names none of `tests/`. No agent of the loop runs the whole suite: only this retro does, once a day.
- So the rule "a behaviour has a test that fails without it" was met, and the tests that guard a copy against its source were outside every run a service patch gets.

**Would it have been caught?** Only by the next retro, as it was.
