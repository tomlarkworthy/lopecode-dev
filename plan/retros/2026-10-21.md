## 2. Diagnosis: no machine moves a `triaged` issue to `ready`

**What happened.** From 10-20 20:56 to 10-21 05:46 UTC no run started. `loop.status` at 05:23: `doable: 0`, `why: "no work"`.
`loop.work` at the same time listed four rows `step: "ready"`, `role: "triager"`, `machineDoable: true`, why "triaged, to
be made ready": `pds-keys`, `i12589-docs-by-reference`, `pds-kernel-route`, `pds-trial`, each in `triaged` 2.4 to 2.6 days
with no `needs-owner` label. The owner took the label off `pds-keys` and the other PDS tasks on 10-18 19:43 ("yes please
unblock all the work", event 15250). Seven more `pds-*` issues wait `after` them, so the PDS project the owner chose on
10-18 stopped when `pds-repo-core` finished at 20:56.

**Since when, and how often.** Over 7 days, 452 moves from `triaged` to `ready`:

```
out-* sessions   341   median wait 0.0 h, max 11.5
claude-session-*  29   max 9.5
triage-* agents   72   max 0.0 h   <- always in the same run that triaged it
unstick-*         10   max 0.0 h
```

No `triaged` issue that waited was ever moved by the machine. A session did each of those by hand.

**Why the system allowed it.** Three texts disagree:
- `roles/triager.md` takes `states: [open, triaged]` and has a section "A `triaged` issue": read the verdict, `move ID ready`.
- `brain-x-loop`'s `owed()` reads that `states` list and marks the row machine-doable.
- `drain.ts` `triable()` filters `i.state === "open"`. The triager is only ever started on `open` issues.

`brain-x-loop` knew about the gap and allowed for it rather than fixing it: line 892 of `brain-loop.js`, "A ready row is
not counted, as the drain takes none of them: a start for it would end at once and repeat at each tick."

**Was "working" checked live?** No. The orchestrating sessions did the step by hand, so the gap only showed when no
session was steering, overnight.

**Would it have been caught without this run?** Only by the owner. At 05:46:23 UTC his own session (`out-0535ef`, note
"move pds-keys to ready (owner asked to start the drain)") moved `pds-keys` by hand. The drain's first move followed 2 s later,
at 05:46:25.
