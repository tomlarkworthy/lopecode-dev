## 3. What others do, and what was not done

A merge queue (Zuul's gate, [Trunk's predictive testing](https://docs.trunk.io/merge-queue/optimizations/predictive-testing), [SubmitQueue](https://github.com/roychying/submitqueue)) tests each queued change on the head it will land on, with the changes ahead of it applied, and removes a change that conflicts with those ahead ([Zuul's description, 2013](https://lists.openstack.org/pipermail/openstack-dev/2013-July/012025.html)). In the terms used here: six reviewed deployer patches would be stacked in one order, each rebased onto the one before and tested once, and the owner would deploy the stack with one click. This run did not build that. It changes `deploy-deployer.ts`, the owner's tool, and whether a review of the stack stands for a review of each patch is his call (section 5). This run did the smaller part: a stale patch is now found and handed back before he clicks, not at his click.
